Şərtlər, Dövrlər və Dinamik Bloklar

DPE-07 · Data Platform & Engineering Bootcamp

İndiyə qədər yazdığımız konfiqurasiyalar sabit idi. Bu fəsildə Terraform-un ən güclü üç vasitəsini öyrənəcəyik: şərti ifadələr (mühitə görə fərqli dəyər seçmək), for dövrləri (siyahı və map üzərində gəzərək çoxlu resurs yaratmaq) və dinamik bloklar (resursun içindəki iç-içə blokları avtomatik generasiya etmək). Bu üçü birlikdə təkrarçılığı aradan qaldırır və konfiqurasiyanı miqyaslana bilən edir.

1 · Şərti ifadələr

Sintaksis

Terraform-da şərti ifadələr bir çox proqramlaşdırma dilindəki üçlü (ternary) operatora bənzəyir və giriş dəyərlərinə əsasən konfiqurasiyanı uyğunlaşdırmağa imkan verir. Format belədir: 

condition ? true_value : false_value
  • condition — yoxlanılan şərt, məsələn var.environment == "production".
  • true_value — şərt doğru olanda işlədilən dəyər.
  • false_value — şərt yanlış olanda işlədilən dəyər.
Şərtin hər iki qolu eyni tipdə olmalıdır. Terraform tipləri avtomatik uyğunlaşdırmağa çalışır, amma məsələn string və list qarışdırılanda plan mərhələsində xəta verir.

Nümunə: mühitə görə instance ölçüsü

Tutaq ki, dev mühitində t2.micro, prod mühitində isə t3.large işlətmək istəyirsiniz. Bunu şərti ifadə ilə həll etmək olar: 

variable "environment" {
  default = "dev"
}

resource "aws_instance" "my_instance" {
  ami = "ami-0c55b159cbfafe1f0"

  # prod-da güclü, digər mühitlərdə ucuz tip
  instance_type = var.environment == "production" ? "t3.large" : "t2.micro"
}

Burada instance_type var.environment dəyərindən asılıdır: mühit production-dursa t3.large, əks halda t2.micro seçilir.

İki-üçdən çox variant olanda üçlü operatoru iç-içə yazmaq əvəzinə locals daxilində map işlədin: local.sizes[var.environment]. Bu, oxunaqlığı xeyli artırır.

Nümunə: resursun şərti yaradılması

Şərti ifadə ilə resursun ümumiyyətlə yaradılıb-yaradılmayacağını da idarə etmək olar. Bu, məsələn load balancer-in yalnız prod mühitində qurulması kimi hallar üçün əlverişlidir. 

resource "aws_elb" "my_elb" {
  # true olanda 1 ədəd, false olanda heç biri
  count = var.create_elb ? 1 : 0

  name               = "my-load-balancer"
  availability_zones = ["us-west-1a", "us-west-1b"]
}

count arqumenti resursun yaradılıb-yaradılmayacağını təyin edir: var.create_elb doğrudursa bir load balancer yaranır, yanlışdırsa heç biri.

count işlədilən resurs siyahıya çevrilir — ona müraciət aws_elb.my_elb[0].dns_name şəklində olur. Resurs yaradılmaya da bilər, ona görə birbaşa indeksə müraciət etməzdən əvvəl one(aws_elb.my_elb[*].dns_name) kimi təhlükəsiz üsullardan istifadə edin.

2 · For dövrləri

Əsas sintaksis

Terraform siyahı və map-lər üzərində gəzmək, beləliklə çoxlu resurs və ya dinamik konfiqurasiya yaratmaq üçün for dövrlərini dəstəkləyir. Eyni resursun bir neçə nüsxəsini qurmaq və ya dəyərlər siyahısına əsasən parametr formalaşdırmaq lazım olanda dövrlər əvəzsizdir. 

# 1) siyahı üzərində gəzmə
[for item in list : item_expression]

# 2) map-in açar və dəyərləri üzərində gəzmə
{for key, value in map : key_expression => value_expression}

Kvadrat mötərizə nəticədə siyahı, fiqurlu mötərizə isə map verir.

Nümunə: bir neçə EC2 instance yaratmaq

Instance tiplərinin siyahısına əsasən bir neçə instance yaratmaq üçün siyahının uzunluğundan istifadə edirik:

variable "instance_types" {
  default = ["t2.micro", "t2.small", "t2.medium"]
}

resource "aws_instance" "my_instances" {
  count = length(var.instance_types)

  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = var.instance_types[count.index]
}
  • count siyahının hər elementi üçün bir EC2 instance yaradır.
  • count.index cari elementin nömrəsini göstərir (0-dan başlayır).
count resursları indeksə görə izləyir. Siyahının ortasından bir element silinsə, ondan sonrakı bütün resurslar sürüşür və Terraform onları silib yenidən yaratmağa çalışır. Elementlərin sabit kimliyi vacibdirsə, count əvəzinə for_each işlədin.

Nümunə: teq-lərin dinamik qurulması

for dövrü ilə resurs atributlarını, məsələn teq-ləri də dinamik formalaşdırmaq olar:

variable "tags" {
  type = map(string)

  default = {
    Name  = "example-instance"
    Owner = "admin"
    Env   = "dev"
  }
}

resource "aws_instance" "my_instance" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"

  # map üzərində gəzərək teq-ləri qururuq
  tags = { for key, value in var.tags : key => value }
}
  • Dövr tags map-i üzərində gəzir və teq-ləri instance-a tətbiq edir.
  • Map-dəki hər açar-dəyər cütü bir teq-ə çevrilir.
Dövr həm də çevirmə üçün əlverişlidir. Məsələn bütün açarları böyük hərflə yazmaq: { for k, v in var.tags : upper(k) => v }, yaxud filtr əlavə etmək: { for k, v in var.tags : k => v if v != "" }.

Nümunə: bir neçə availability zone üzrə subnet

variable "availability_zones" {
  default = ["us-west-1a", "us-west-1b"]
}

resource "aws_subnet" "my_subnets" {
  count = length(var.availability_zones)

  vpc_id = aws_vpc.my_vpc.id

  # hər zona üçün ayrıca alt-şəbəkə hesablanır
  cidr_block        = cidrsubnet("10.0.0.0/16", 8, count.index)
  availability_zone = var.availability_zones[count.index]
}

Dövr availability zone-ların siyahısı üzrə gəzir və hər birində bir subnet yaradır. cidrsubnet funksiyası isə əsas CIDR blokunu bölərək hər subnet üçün ayrı diapazon hesablayır — diapazonları əl ilə yazmağa ehtiyac qalmır.

3 · Dinamik bloklar

Dinamik blok nədir

Dinamik bloklar resursun daxilində iç-içə blokları avtomatik generasiya etməyə imkan verir: neçə blok yaradılacağını və hər birinin məzmununu dəyişənlərlə idarə edirsiniz. Bu, security group, load balancer və network ACL kimi çoxlu iç-içə blok tələb edən resurslarda xüsusilə faydalıdır.

  • for_each — üzərində gəzilən kolleksiyanı (siyahı və ya map) təyin edir.
  • content — hər element üçün generasiya olunacaq blokun məzmununu təyin edir.
  • iterator — dövr dəyişəninin adı (susmaya görə blokun öz adı, məsələn ingress).

Şərti ifadəTək dəyər seçirMühitə görə instance tipi

Nümunə: dinamik security group qaydaları

Fərqli portlar üçün bir neçə security group qaydası lazımdırsa, portlar siyahısı üzərində dinamik blokla gəzmək olar:

variable "allowed_ports" {
  default = [22, 80, 443]
}

resource "aws_security_group" "my_sg" {
  name = "example-sg"

  dynamic "ingress" {
    for_each = var.allowed_ports

    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}
  • Dinamik blok allowed_ports dəyişəni üzərində gəzir və hər port üçün ayrıca ingress bloku yaradır.
  • ingress.value dövrün cari elementinə — yəni cari porta — müraciət edir.
Nümunədəki 0.0.0.0/0 dəyəri qaydanı bütün internetə açır. Öyrənmə məqsədilə uyğundur, lakin əsl mühitlərdə, xüsusilə 22-ci port üçün, mütləq konkret IP diapazonu göstərin.

Nümunə: autoscaling siyasətləri

Eyni yanaşma ilə bir tətbiq üçün bir neçə autoscaling siyasəti qurmaq olar:

variable "scaling_policies" {
  default = {
    scale_up   = { adjustment = 2,  cooldown = 300 }
    scale_down = { adjustment = -1, cooldown = 300 }
  }
}

resource "aws_autoscaling_policy" "my_policy" {
  for_each = var.scaling_policies

  name                   = "${each.key}-policy"
  scaling_adjustment     = each.value.adjustment
  cooldown               = each.value.cooldown
  adjustment_type        = "ChangeInCapacity"
  autoscaling_group_name = aws_autoscaling_group.my_asg.name
}
  • for_each map üzərində gəzərək iki siyasət (artırma və azaltma) yaradır.
  • each.key siyasətin adını (scale_up, scale_down), each.value isə onun parametrlərini verir.
  • Hər siyasətin scaling_adjustment və cooldown dəyərləri fərqlidir.
for_each resursları indeksə deyil, açara bağlayır: müraciət aws_autoscaling_policy.my_policy["scale_up"] şəklində olur. Map-dən bir element silinsə, yalnız ona uyğun resurs silinir — qalanlar toxunulmaz qalır.

Dinamik blokları nə vaxt işlətməli

Dinamik bloklar bu hallarda faydalıdır:

  • Eyni tipli çoxlu iç-içə blok lazım olanda — security group qaydaları, autoscaling siyasətləri, listener-lər.
  • Blokların sayı və ya məzmunu giriş dəyişənlərindən asılı olaraq dəyişəndə.

Dinamik bloklar konfiqurasiyadakı təkrarçılığı azaldır və oxşar blokları əl ilə yazmaq ehtiyacını aradan qaldırır.

Hər şeyi dinamik etməyin. Cəmi iki-üç sabit blok varsa, onları sadəcə açıq yazmaq daha oxunaqlıdır. Dinamik bloklar konfiqurasiyanı gücləndirir, amma eyni zamanda oxumağı və debug etməyi çətinləşdirir — plan çıxışında blokun haradan gəldiyini görmək asan olmur.

4 · Yekun

Yadda saxla

  • Şərti ifadə condition ? doğru : yanlış formasındadır; hər iki qol eyni tipdə olmalıdır.
  • count = şərt ? 1 : 0 — resursun yaradılıb-yaradılmayacağını idarə etməyin ən sadə yoludur.
  • for ifadələri siyahı ([for ...]) və ya map ({for ... => ...}) qaytarır — teq, ad və CIDR hesablamaları üçün əvəzsizdir.
  • count indeksə, for_each açara bağlıdır: ortadan element silinməsi vacibdirsə, for_each seçin.
  • dynamic bloklar resurs daxilində iç-içə blokları generasiya edir — təkrarçılığı azaldır, amma yalnız blok sayı həqiqətən dəyişkən olanda işlədin.
