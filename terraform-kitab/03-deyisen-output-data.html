Dəyişənlər, Output-lar və Data Source-lar

DPE-07 · Data Platform & Engineering Bootcamp

Bu üç mexanizm Terraform konfiqurasiyasını sabit mətn yığınından çevik və təkrar istifadəyə yararlı koda çevirir. Dəyişənlər dəyərləri kənardan alır, output-lar infrastrukturdan məlumat çıxarır, data source-lar isə Terraform-un idarə etmədiyi mövcud resursları konfiqurasiyaya bağlayır.

1 · Terraform-da dəyişənlər

Dəyişənlər nə üçündür

Terraform-da dəyişənlər konfiqurasiya fayllarını parametrləşdirməyə imkan verir. Dəyərləri koda sabit yazmaq (hardcode) əvəzinə dəyişən təyin edib onu konfiqurasiyanın hər yerində işlədirsən. Bu, kodu daha modul quruluşlu və təkrar istifadəyə yararlı edir — xüsusilə development, staging və prod kimi müxtəlif mühitlərlə işlədikdə.

a. Dəyişənlərin təyini

Terraform-da dəyişənlər variable bloku ilə təyin olunur. Hər dəyişən aşağıdakı atributlara malik ola bilər:

AtributTəyinatı
defaultDəyişənin standart dəyəri
typeDəyişənin tipi (məsələn string, list, map)
descriptionDəyişənin nəyi ifadə etdiyini izah edən qısa təsvir
sensitiveDəyişəni həssas kimi işarələyir — dəyəri log-larda və output-larda görünmür

AWS regionu üçün sadə string dəyişəninin təyini:

variable "aws_region" {
  default     = "us-west-1"
  description = "Resursların yerləşdiriləcəyi AWS regionu."
}

Burada aws_region adlı dəyişən təyin olunub, standart dəyəri "us-west-1"-dir. description dəyişənin nə üçün olduğunu izah edir.

Məsləhət. description-u həmişə yaz. Konfiqurasiyanı altı ay sonra oxuyan (bəlkə də sən özün olacaqsan) hər dəyişənin niyə mövcud olduğunu bilməlidir. Bu təsvirlər həm də avtomatik sənədləşdirmə alətləri tərəfindən oxunur.

b. Dəyişən tipləri

Terraform bir neçə dəyişən tipini dəstəkləyir:

  • String — tək dəyər, məsələn region və ya instance tipi.
  • List — dəyərlər toplusu. Bir neçə instance, subnet və s. təyin etmək üçün faydalıdır.
  • Map — açar-dəyər cütlərindən ibarət toplu. Konfiqurasiya seçimlərini nizamlı formada göstərmək üçün əlverişlidir.
  • Boolean — true və ya false dəyəri.

List dəyişəni nümunəsi:

variable "instance_types" {
  type    = list(string)
  default = ["t2.micro", "t2.small", "t2.medium"]
}

Map dəyişəni nümunəsi:

variable "ami_ids" {
  type = map(string)

  default = {
    us-east-1 = "ami-123456"
    us-west-1 = "ami-654321"
  }
}

Bu tiplər sayəsində daxil olan dəyərlərə uyğunlaşan dinamik konfiqurasiyalar qura bilərsən.

c. Dəyişənlərin konfiqurasiyada işlədilməsi

Dəyişənləri təyin etdikdən sonra onlara resurs təsvirlərində var. prefiksi ilə müraciət edirsən:

resource "aws_instance" "my_instance" {
  ami           = var.ami_ids[var.aws_region]
  instance_type = var.instance_type
}

Bu nümunədə:

  • var.ami_ids[var.aws_region] regiondan asılı olaraq uyğun AMI-ni dinamik şəkildə seçir.
  • var.instance_type instance tipini dəyişəndən götürür.
Qeyd. Map-dən açar üzrə seçim (var.ami_ids[var.aws_region]) regiondan asılı dəyərləri idarə etməyin ən təmiz üsuludur. Açar map-də yoxdursa, Terraform plan mərhələsində səhv verəcək — bu, səhvin erkən tutulması deməkdir.

d. Dəyişənlərə dəyər ötürmək

Terraform-da dəyişənlərə dəyər vermək üçün bir neçə yol var.

1. Standart dəyərlər

Heç bir dəyər verilmirsə, Terraform variable blokunda göstərilmiş default dəyərindən istifadə edir.

2. Əmr sətri bayraqları

Dəyişənləri birbaşa terraform apply və ya terraform plan əmrinə -var bayrağı ilə ötürə bilərsən:

terraform apply -var="aws_region=us-east-1"

3. Mühit dəyişənləri

Dəyişənləri mühit dəyişənləri vasitəsilə də təyin etmək olar. Məsələn, AWS regionunu ötürmək üçün:

export TF_VAR_aws_region=us-east-1
terraform apply

4. .tfvars faylları

Dəyişənləri ayrıca .tfvars faylında təyin edib icra zamanı Terraform-a ötürmək mümkündür. terraform.tfvars faylı nümunəsi:

aws_region    = "us-east-1"
instance_type = "t2.medium"

Terraform-u belə işlədirsən:

terraform apply -var-file="terraform.tfvars"
ÜsulNə vaxt uyğundur
defaultAğlabatan standart dəyər olduqda
-varBirdəfəlik, sınaq məqsədli dəyişikliklər
TF_VAR_*CI/CD pipeline-ları və secret idarəsi
.tfvarsHər mühit üçün ayrıca dəyər dəsti (dev.tfvars, prod.tfvars)
Məsləhət. terraform.tfvars adlı fayl avtomatik oxunur — onu -var-file ilə göstərməyə ehtiyac yoxdur. Mühitlərə görə ayrılmış fayllar üçün isə (prod.tfvars) bayraq mütləqdir. Həssas dəyərlər olan .tfvars fayllarını .gitignore-a əlavə et.

e. Həssas dəyişənlər

Bəzən API açarı, verilənlər bazası parolu və ya SSH xüsusi açarı kimi həssas məlumatları ötürmək lazım gəlir. Terraform dəyişəni sensitive kimi işarələməyə imkan verir — belə dəyişənlərin dəyəri log-larda və output-larda göstərilmir.

variable "db_password" {
  type      = string
  sensitive = true
}

sensitive bayrağı true olduqda Terraform db_password dəyərinin terraform apply və ya terraform plan zamanı ekrana çıxmamasını təmin edir.

Xəbərdarlıq. sensitive = true yalnız ekranda görünməni bağlayır — dəyər yenə də state faylında açıq mətnlə saxlanılır. Ona görə state-in şifrələnməsi (S3-də encryption) və girişin məhdudlaşdırılması vacibdir.

2 · Terraform-da output-lar

Output-lar nə üçündür

Output-lar infrastrukturdan məlumat çıxarmağa və onu paylaşmağa imkan verir. Onlar resurslar qurulduqdan sonra vacib məlumatları göstərmək və ya Terraform module-ları arasında dəyər ötürmək üçün işlədilir.

a. Output-un təyini

Output output bloku ilə təyin olunur. Hər output bloku aşağıdakıları saxlaya bilər:

  • value — çıxarılacaq dəyər (adətən hansısa resursun atributunun nəticəsi).
  • description — output-un qısa təsviri (məcburi deyil).
  • sensitive — true olduqda dəyər Terraform log-larında göstərilmir.

Nümunə: EC2 instance-ın public IP ünvanı üçün output:

output "instance_public_ip" {
  value       = aws_instance.my_instance.public_ip
  description = "EC2 instance-ın public IP ünvanı."
}

Bu nümunədə value aws_instance resursundan public_ip atributunu götürür, description isə bu output-un nəyi ifadə etdiyini izah edir.

b. Output-lara baxmaq

Konfiqurasiya tətbiq olunduqdan sonra output-lara terraform output əmri ilə baxa bilərsən:

terraform output

Bu əmr konfiqurasiyada təyin olunmuş bütün output-ları göstərir. Yalnız bir output-a baxmaq üçün:

terraform output instance_public_ip

Bu, sadəcə instance_public_ip output-unun dəyərini göstərəcək.

Qeyd. terraform output -json nəticəni maşın oxuyan formatda verir — CI/CD skriptlərində və jq ilə emal zamanı çox faydalıdır.

c. Output-ların module-lar arasında işlədilməsi

Output-ların ən güclü işlədilmə sahələrindən biri Terraform module-ları arasında məlumat paylaşmaqdır. Bir neçə module ilə işləyəndə bir module-un output-u digər module üçün giriş dəyəri (input) ola bilər.

# Module 1: VPC module-u
module "vpc" {
  source = "./modules/vpc"
}

# Module 2: VPC module-undan asılı olan EC2 module-u
module "ec2" {
  source     = "./modules/ec2"
  vpc_id     = module.vpc.vpc_id # VPC module-unun output-u işlədilir
  subnet_ids = module.vpc.subnet_ids
}

Burada vpc module-undan gələn vpc_id və subnet_ids dəyərləri ec2 module-una giriş kimi ötürülür.

Məsləhət. Module-un output-ları onun ictimai interfeysidir. Yalnız kənardan həqiqətən lazım olan dəyərləri output kimi aç — hər atributu açmaq module-un daxili quruluşunu istifadəçilərə "sızdırır" və sonradan dəyişməyi çətinləşdirir.

d. Həssas output-lar

Həssas dəyişənlərdə olduğu kimi, Terraform output-ları da sensitive kimi işarələməyə imkan verir. Bu, parol və ya xüsusi açar kimi məlumatların output log-larında görünməməsini təmin edir.

output "db_password" {
  value     = aws_db_instance.my_db.password
  sensitive = true
}

3 · Data source-lar

a. Data source nədir

Data source-lar Terraform-dan kənarda mövcud olan infrastruktura sorğu göndərməyə və ona istinad etməyə imkan verir. Bu, başqa komanda, layihə və ya proses tərəfindən idarə olunan, lakin sənin konfiqurasiyana daxil edilməli olan resurslarla işləyəndə faydalıdır.

Data source mövcud infrastruktur komponentləri haqqında məlumat oxumağa imkan verir. Data source-lar yeni resurs yaratmır — onlar sadəcə artıq mövcud olan resurslar haqqında məlumat gətirir.

Məsələn, mövcud AWS VPC-nin ID-sini əldə edib öz konfiqurasiyanda işlətmək istəyə bilərsən.

b. Data source-ların işlədilməsi

Data source işlətmək üçün konfiqurasiyada data bloku yazılır. data blokunun formatı resource blokuna bənzəyir, lakin o, resurs yaratmır və ya dəyişmir — yalnız məlumat gətirir.

Nümunə: mövcud AWS VPC-yə sorğu:

data "aws_vpc" "default" {
  default = true
}

resource "aws_instance" "my_instance" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  subnet_id     = data.aws_vpc.default.id # VPC data source-undan istifadə
}

Bu nümunədə data bloku AWS-dəki standart VPC-yə sorğu göndərir və onun ID-sini götürür. Həmin ID sonra eyni VPC daxilində EC2 instance yaratmaq üçün işlədilir.

Qeyd. Data source-a müraciət data. prefiksi ilə başlayır: data.<TİP>.<AD>.<ATRIBUT>. Resurslarda isə prefiks olmur: aws_instance.my_instance.id.

c. Geniş yayılmış data source-lar

Terraform müxtəlif provider-lər üzrə çoxlu data source təqdim edir. Ən çox işlədilənlərdən bəziləri:

ProviderData sourceNə gətirir
AWSaws_vpcMövcud VPC haqqında məlumat
aws_amiƏlçatan AMI-lər (Amazon Machine Image) üzrə sorğu
aws_subnetMövcud subnet haqqında məlumat
Azureazurerm_resource_groupMövcud resource group haqqında məlumat
azurerm_virtual_networkMövcud virtual şəbəkə haqqında məlumat
Google Cloudgoogle_compute_networkMövcud Google Cloud şəbəkəsi haqqında məlumat
google_compute_subnetworkMövcud subnetwork haqqında məlumat

d. Nümunə: çoxbuludlu mühitdə data source-lar

İndi daha mürəkkəb bir nümunəyə baxaq — həm AWS-dən, həm də Google Cloud-dan data source-lar vasitəsilə məlumat götürürük.

# Data source: standart AWS VPC-yə sorğu
data "aws_vpc" "default" {
  default = true
}

# Data source: Google Cloud storage bucket-inə sorğu
data "google_storage_bucket" "my_bucket" {
  name = "my-existing-bucket"
}

# AWS VPC məlumatı ilə EC2 instance yaradılması
resource "aws_instance" "my_instance" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  subnet_id     = data.aws_vpc.default.subnets[0].id
}

# Google Cloud bucket məlumatının output-da işlədilməsi
output "bucket_location" {
  value = data.google_storage_bucket.my_bucket.location
}

Bu nümunədə:

  • Standart AWS VPC aws_vpc data source-u ilə sorğulanır və subnet ID-si EC2 instance yaratmaq üçün işlədilir.
  • Mövcud Google Cloud Storage bucket-i google_storage_bucket data source-u ilə sorğulanır və onun yerləşdiyi region infrastruktur tətbiq olunduqdan sonra output kimi göstərilir.

e. Data source-ların faydaları

Data source-lar Terraform konfiqurasiyalarını daha dinamik və çevik etmək üçün son dərəcə faydalıdır:

  • Mövcud infrastruktura problemsiz qoşulma. Terraform-dan kənarda idarə olunan resurslarla işləməyə imkan verir — onları yenidən yaratmağa ehtiyac qalmır.
  • Layihələr arası təkrar istifadə. Komandalar və ya layihələr arasında ortaq infrastruktur resurslarına birbaşa sahiblik etmədən istinad edə bilərsən.
  • Təkrar resurs yaradılmasının qarşısını alır. Mövcud resursları sorğulamaqla infrastruktur komponentlərinin təsadüfən ikiləşməsindən qorunursan.
Əlavə fikir. Data source-lar konfiqurasiyanı xarici vəziyyətə bağlayır. Sorğulanan resurs başqası tərəfindən silinsə və ya adı dəyişsə, sənin plan-ın sınacaq. Ona görə həssas asılılıqlarda dəqiq filtr işlət (məsələn tag üzrə) və nəyə güvəndiyini kod içində şərhlə qeyd et.

4 · Yekun

Bu fəsildə Terraform-da dəyişənlər, output-lar və data source-lar mövzularını nəzərdən keçirdik. Bunlar infrastruktur kodunu dinamik, təkrar istifadəyə yararlı və çevik etməyin əsas komponentləridir:

  • Dəyişənlər konfiqurasiyanı parametrləşdirir və mühitlər arasında çeviklik yaradır.
  • Output-lar resurslar haqqında vacib məlumatı üzə çıxarır — bu məlumat başqa module-lara və ya sistemlərə ötürülə bilər.
  • Data source-lar mövcud infrastrukturu sorğulamağa imkan verir və Terraform-u başqa komandaların, yaxud provider-lərin idarə etdiyi infrastruktur ilə birləşdirir.

Növbəti fəsildə state idarəsi, remote state və backend-lər mövzusuna keçirik. Bunlar Terraform-un infrastrukturu komanda üzvləri və mühitlər arasında ardıcıl şəkildə idarə etməsi üçün həlledicidir.

5 · Yadda saxla

  • Dəyişən variable bloku ilə təyin olunur, konfiqurasiyada var.<ad> ilə işlədilir; type və description yazmaq vərdiş olmalıdır.
  • Dəyər ötürməyin dörd yolu var: default, -var, TF_VAR_* mühit dəyişəni və .tfvars faylı.
  • sensitive = true dəyəri ekrandan gizlədir, amma state faylından gizlətmir — state-i şifrələ.
  • Output-lar həm istifadəçiyə məlumat göstərir, həm də module-lar arasında dəyər ötürməyin əsas yoludur.
  • Data source-lar oxuyur, yaratmır: mövcud VPC, AMI, subnet kimi resursları konfiqurasiyaya bağlayır.
  • Data source-a müraciət data. prefiksi ilə, resursa müraciət isə prefiksiz olur.
