Hibrid Cloud

DPE-07 · Data Platform & Engineering Bootcamp

Əksər təşkilat buluda bir gecədə keçmir — köhnə sistemlər öz serverlərində qalır, yeni tətbiqlər isə buludda qurulur. Hibrid cloud məhz bu iki dünyanın birgə yaşamasıdır. Bu fəsildə on-prem şəbəkənin AWS-ə Site-to-Site VPN, Azure-a isə ExpressRoute vasitəsilə uzadılmasını, vSphere kimi on-prem provider-lərlə işi və hibrid mühit üçün əməli qaydaları öyrənəcəyik.

1 · Hibrid cloud nədir və nə üçün seçilir

Tərif

Hibrid cloud öz data mərkəzinizin, private cloud-un və public cloud-un (AWS, Azure, Google Cloud) birgə istifadəsidir. Təşkilatlar bu memarlığa üç səbəbdən üstünlük verir:

  • Nəzarəti saxlamaq — həssas data və ya tənzimləyici tələblər bəzi iş yüklərinin fiziki olaraq öz data mərkəzinizdə qalmasını tələb edir. Bank, tibb və dövlət sektorunda bu, seçim deyil, öhdəlikdir.
  • Bulud resurslarından yararlanmaq — dinamik miqyaslanma tələb edən iş yükləri (müştəriyə baxan tətbiqlər, kampaniya dövrünün pik yükü, qısamüddətli hesablama işləri) buludda daha ucuz və çevik işləyir.
  • Xərcə nəzarət — artıq alınmış on-prem avadanlıq amortizasiya olunana qədər əsas sistemləri saxlayır, kritik olmayan yükləri isə buluda köçürürsünüz.

Belə mühiti idarə etmək mürəkkəbdir, lakin Terraform hər iki tərəf üçün vahid infrastructure-as-code yanaşması təklif edərək bu mürəkkəbliyi bir dilə yığır.

2 · Açar anlayışlar

a. On-prem şəbəkənin buluda uzadılması

Hibrid quruluşun əsas məqsədi mövcud şəbəkəni buluda uzatmaqdır — yəni bulud VPC-si sanki sizin data mərkəzinizin daha bir subnet-i kimi davransın. Bu, VPN və ya Direct Connect / ExpressRoute kimi xüsusi xətlərlə həyata keçirilir.

b. Vahid idarəetmə

Terraform həm bulud, həm on-prem resursları üçün eyni konfiqurasiya dilini işlədir. Nəticədə bütün infrastruktura tək pəncərədən baxa, dəyişiklikləri eyni review və CI axınından keçirə bilirsiniz.

c. Multi-cloud inteqrasiyası

Hibrid quruluşlarda tez-tez birdən çox bulud iştirak edir — məsələn hesablama gücü AWS-də, verilənlər bazası xidmətləri Azure-da. Terraform-un çoxlu provider dəstəyi bunları bir konfiqurasiyada birləşdirməyə imkan verir.

VPN internet üzərindən şifrələnmiş tunel qurur — ucuzdur və dəqiqələr ərzində qalxır, lakin gecikmə internetdən asılıdır. Direct Connect və ExpressRoute isə fiziki ayrılmış xətdir: sabit gecikmə və yüksək buraxma qabiliyyəti verir, amma provider ilə müqavilə və həftələrlə qurulma müddəti tələb edir.

3 · On-prem şəbəkəni AWS-ə uzatmaq

Bu nümunədə mövcud on-prem şəbəkəni AWS Site-to-Site VPN vasitəsilə AWS VPC-yə bağlayırıq. Başlanğıc fərziyyəsi: on-prem tərəfdə 192.168.1.0/24 private subnet-i və ictimai IP-yə malik VPN gateway var.

Addım 1 — Provider

provider "aws" {
  region = "us-west-2"
}

Addım 2 — VPC və subnet

resource "aws_vpc" "my_vpc" {
  cidr_block = "10.0.0.0/16"

  tags = {
    Name = "HybridCloudVPC"
  }
}

resource "aws_subnet" "my_subnet" {
  vpc_id            = aws_vpc.my_vpc.id
  cidr_block        = "10.0.1.0/24"
  availability_zone = "us-west-2a"
}

Burada 10.0.0.0/16 CIDR bloku ilə VPC və onun daxilində iş yükləri üçün subnet yaradılır.

Hibrid quruluşda ən vacib planlaşdırma qərarı CIDR seçimidir. On-prem şəbəkə ilə VPC-nin ünvan aralıqları üst-üstə düşməməlidir — üst-üstə düşən diapazonlarda routing qeyri-mümkün olur və problemi sonradan həll etməyin yeganə yolu VPC-ni yenidən qurmaqdır. Layihəyə başlamazdan əvvəl şirkət miqyasında ünvan planı hazırlayın.

Addım 3 — Virtual Private Gateway

resource "aws_vpn_gateway" "my_vgw" {
  vpc_id = aws_vpc.my_vpc.id
}

Virtual Private Gateway (VGW) yaradılır və VPC-yə qoşulur — bu, VPN-in AWS tərəfdəki bağlantı nöqtəsidir.

Addım 4 — Customer Gateway və VPN bağlantısı

resource "aws_customer_gateway" "on_prem_gateway" {
  bgp_asn    = 65000
  ip_address = "1.2.3.4"   # on-prem gateway-in ictimai IP-si
  type       = "ipsec.1"
}

resource "aws_vpn_connection" "vpn_conn" {
  vpn_gateway_id      = aws_vpn_gateway.my_vgw.id
  customer_gateway_id = aws_customer_gateway.on_prem_gateway.id
  type                = "ipsec.1"
  static_routes_only  = true

  tags = {
    Name = "OnPremToAWS-VPN"
  }
}

resource "aws_vpn_connection_route" "route" {
  vpn_connection_id      = aws_vpn_connection.vpn_conn.id
  destination_cidr_block = "192.168.1.0/24"  # on-prem CIDR bloku
}

Bu konfiqurasiyada üç şey baş verir: Customer Gateway on-prem tərəfdəki VPN cihazını ictimai IP və ASN ilə təsvir edir; VPN Connection AWS VPC ilə on-prem şəbəkə arasında IPsec tunelini qurur; VPN Connection Route isə on-prem CIDR blokuna gedən trafikin tuneldən keçməsini təmin edir.

Terraform tunelin AWS tərəfini qurur, lakin on-prem cihazın (Cisco, Fortinet, pfSense) konfiqurasiyasını yox. AWS konsolundan və ya aws ec2 describe-vpn-connections ilə hazır konfiqurasiya faylını yükləyib şəbəkə komandasına verin. Tunel yalnız hər iki tərəf qurulandan sonra UP vəziyyətinə keçir.
static_routes_only = true sadə quruluşlar üçün uyğundur. Şəbəkə tez-tez dəyişirsə və ya birdən çox filial varsa, BGP dinamik marşrutlaşdırma daha yaxşıdır — bu halda static_routes_only-ni false qoyub bgp_asn ilə işləyin.

4 · On-prem şəbəkəni Azure-a ExpressRoute ilə uzatmaq

ExpressRoute on-prem şəbəkə ilə Azure data mərkəzləri arasında internetdən keçməyən özəl bağlantı yaradır. Sabit gecikmə və yüksək buraxma qabiliyyəti tələb olunan hallarda seçilir.

Addım 1 — Provider və virtual şəbəkə

provider "azurerm" {
  features {}
}

resource "azurerm_virtual_network" "my_vnet" {
  name                = "my-vnet"
  address_space       = ["10.1.0.0/16"]
  location            = "West US"
  resource_group_name = azurerm_resource_group.my_rg.name
}

Addım 2 — ExpressRoute circuit

resource "azurerm_express_route_circuit" "my_circuit" {
  name                  = "my-expressroute-circuit"
  location              = "West US"
  resource_group_name   = azurerm_resource_group.my_rg.name
  service_provider_name = "Equinix"          # bağlantı provayderi
  peering_location      = "Silicon Valley"   # fiziki qoşulma nöqtəsi
  bandwidth_in_mbps     = 1000                # 1 Gbps

  sku {
    tier   = "Standard"
    family = "MeteredData"              # ödəniş həcmə görə
  }
}

Burada Equinix kimi bir xidmət provayderi üzərindən 1 Gbps buraxma qabiliyyətli circuit yaradılır və ödəniş modeli olaraq həcmə görə hesablama (MeteredData) seçilir.

Addım 3 — Virtual Network Gateway

resource "azurerm_virtual_network_gateway" "vpn_gateway" {
  name                = "vpn-gateway"
  location            = "West US"
  resource_group_name = azurerm_resource_group.my_rg.name
  type                = "ExpressRoute"
  vpn_type            = "RouteBased"
  sku                 = "Standard"

  ip_configuration {
    name                 = "gw-ipconfig"
    public_ip_address_id = azurerm_public_ip.gw_ip.id
    subnet_id            = azurerm_subnet.gateway_subnet.id
  }
}

Bu gateway Azure tərəfdə ExpressRoute bağlantısını qəbul edir. Diqqət: Azure gateway-i mütləq adı GatewaySubnet olan xüsusi subnet-də yerləşməlidir.

ExpressRoute circuit-i Terraform yaradır, amma o dərhal işə düşmür: fiziki qoşulmanı xidmət provayderi (Equinix, Megaport və s.) tamamlamalıdır. apply-dan sonra circuit NotProvisioned vəziyyətində qalır — bu, xəta deyil, gözlənilən haldır. Gateway resursunun yaradılması isə tək başına 30–45 dəqiqə çəkə bilər, buna görə CI timeout dəyərlərini artırın.

5 · On-prem resursların Terraform ilə idarəsi

Terraform yalnız bulud üçün deyil: VMware vSphere, OpenStack, Nutanix və Kubernetes üçün də provider-lər mövcuddur. Bunlar sayəsində on-prem virtual maşınları, saxlama və şəbəkə resurslarını bulud resursları ilə eyni üslubda təsvir edə bilirsiniz.

provider "vsphere" {
  vsphere_server       = "vsphere.local"
  user                 = var.vsphere_user
  password             = var.vsphere_password
  allow_unverified_ssl = true   # yalnız laboratoriya üçün
}

resource "vsphere_virtual_machine" "vm" {
  name             = "terraform-vm"
  resource_pool_id = data.vsphere_resource_pool.pool.id
  datastore_id     = data.vsphere_datastore.datastore.id

  num_cpus = 2
  memory   = 4096
  guest_id = "rhel7_64Guest"

  network_interface {
    network_id   = data.vsphere_network.network.id
    adapter_type = "vmxnet3"
  }

  disk {
    label            = "disk0"
    size             = 40
    thin_provisioned = true
  }
}

Bu nümunədə Terraform vSphere virtual maşınını — CPU, yaddaş, disk və şəbəkə interfeysi ilə birlikdə — idarə edir. Həmin maşın sonra bulud resurslarına bağlanaraq daha geniş hibrid strategiyanın bir hissəsinə çevrilir.

allow_unverified_ssl = true sertifikat yoxlamasını tamamilə söndürür və man-in-the-middle hücumuna qapı açır. Yalnız test laboratoriyasında işlədin; işlək mühitdə vCenter-ə düzgün sertifikat quraşdırın və bu parametri false saxlayın.
On-prem provider-lər bulud API-lərindən daha ləng cavab verir və şəbəkə əlçatanlığı tələb edir. Bu səbəbdən Terraform-un on-prem hissəsini bulud hissəsindən ayrı state-də saxlamaq (və gərəkdikdə terraform_remote_state ilə əlaqələndirmək) plan vaxtını və nasazlıq təsirini azaldır.

6 · Əməli qaydalar

a. Mərkəzləşdirilmiş loglama və monitorinq

On-prem və bulud resurslarının logları eyni yerdə toplanmalıdır. CloudWatch, Azure Monitor və Prometheus hər iki mühitdən metrika və log qəbul edə bilir. İki ayrı panel arasında keçid etmək araşdırma vaxtını xeyli uzadır.

b. Ardıcıl teq və adlandırma

Eyni adlandırma konvensiyasını hər iki tərəfdə tətbiq edin. Bu, resursların izlənməsini, xərc hesabatını və avtomatlaşdırmanı asanlaşdırır — env-app-role-nn kimi sadə bir şablon uzun müddət işləyir.

c. Təhlükəsiz şəbəkə bağlantısı

On-prem ilə bulud arasındakı VPN və ya özəl xətlər şifrələnmiş olmalı, hər iki tərəfdə firewall qaydaları ilə məhdudlaşdırılmalıdır. Tunel qurulduqdan sonra "hər şey hər şeyə çıxa bilsin" qaydası qoymaq hibrid quruluşlarda ən çox rast gəlinən təhlükəsizlik səhvidir — yalnız lazım olan port və subnet-lərə icazə verin.

AI ilə iş: hibrid şəbəkə konfiqurasiyası istəyəndə CIDR bloklarını, ASN-i və provider versiyasını prompt-da açıq göstərin. Model şəbəkə topologiyasını görmədiyi üçün üst-üstə düşən CIDR-lər və ya mövcud olmayan arqumentlər təklif edə bilir. Yaradılan konfiqurasiyanı əvvəlcə terraform validate, sonra izolyasiya olunmuş test hesabında plan ilə yoxlayın — səhv VPN routing-i bütün ofis şəbəkəsini kəsə bilər.

7 · Yadda saxla

  • Hibrid cloud on-prem nəzarəti ilə buludun çevikliyini birləşdirir; Terraform hər iki tərəf üçün vahid konfiqurasiya dili verir.
  • AWS tərəfdə bağlantı üç resursdan qurulur: aws_vpn_gateway, aws_customer_gateway və aws_vpn_connection; marşrut isə ayrıca təyin olunur.
  • Azure-da ExpressRoute circuit-i Terraform yaradır, lakin fiziki qoşulmanı xidmət provayderi tamamlayır — circuit bir müddət NotProvisioned qalır.
  • CIDR blokları on-prem ilə üst-üstə düşməməlidir; bu səhvin sonradan düzəldilməsi VPC-nin yenidən qurulması deməkdir.
  • vSphere, OpenStack və Kubernetes provider-ləri on-prem resursları da eyni HCL sintaksisi ilə idarə etməyə imkan verir.
  • Vahid monitorinq, ardıcıl adlandırma və dar icazəli təhlükəsiz şəbəkə qaydaları hibrid quruluşu idarə oluna bilən saxlayır.
