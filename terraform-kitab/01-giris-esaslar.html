Giriş və Əsaslar

DPE-07 · Data Platform & Engineering Bootcamp

Bu fəsildə Terraform-un nə olduğunu, Infrastructure as Code yanaşmasının hansı problemi həll etdiyini və Terraform-un daxildə necə işlədiyini öyrənəcəksən. Sonra alətin quraşdırılmasını edib ilk konfiqurasiyanı yazacaq, init → plan → apply → destroy dövrəsini əldən keçirəcəksən. Bu fəsil sonrakı bütün mövzuların təməlidir.

1 · Terraform nədir

Qısa tərif

Terraform — HashiCorp tərəfindən hazırlanmış açıq mənbəli Infrastructure as Code (IaC) alətidir. O, infrastruktur resurslarını konfiqurasiya faylları vasitəsilə təyin etməyə, yaratmağa və idarə etməyə imkan verir. İdarə olunan resurslar fiziki və ya virtual ola bilər: serverlər, verilənlər bazaları, şəbəkə komponentləri, yaddaş (storage) və hətta Kubernetes klasterləri.

Konfiqurasiyalar HCL (HashiCorp Configuration Language) adlanan deklarativ dildə yazılır. HCL həm öyrənməsi asan, həm də kifayət qədər güclü bir dildir.

Terraform-un əsas gücü ondadır ki, infrastruktur idarəsini sadə deklarativ modelə çevirir. Bulud provayderinin idarə panelində resursları əl ilə yaratmaq və ya onları avtomatlaşdırmaq üçün skript yazmaq əvəzinə, sən sadəcə infrastrukturun necə görünməli olduğunu təsvir edirsən — qalanını Terraform öz üzərinə götürür.

Terraform geniş yayılıb, çünki bir çox mühiti eyni alətlə idarə edə bilir: AWS, Azure, Google Cloud, həmçinin VMware və OpenStack kimi provider-lər vasitəsilə on-premise mühitlər. Provayderdən asılı olmayaraq bütün infrastrukturu bir yerdən idarə edirsən.

2 · Infrastructure as Code (IaC)

Anlayış

Terraform-u yaxşı başa düşmək üçün əvvəlcə IaC anlayışını mənimsəmək lazımdır. IaC infrastrukturun yaradılmasını və idarəsini kod vasitəsilə — deklarativ və ya imperativ şəkildə — avtomatlaşdırmağa imkan verir. Hər resursu bulud konsolundan və ya əmr sətrindən əl ilə tənzimləmək əvəzinə, sən infrastrukturun arzu olunan vəziyyətini təsvir edirsən, IaC aləti isə onu həyata keçirir.

IaC-in əsas faydaları

FaydaNə deməkdir
Ardıcıllıq (Consistency)Eyni infrastruktur quruluşu bütün mühitlərdə təkrarlanır — development, staging, prod arasında fərq yaranmır.
Versiya nəzarətiKonfiqurasiyalar Git kimi sistemlərdə saxlanılır: dəyişiklikləri izləmək, geri qaytarmaq (rollback) və komanda ilə birgə işləmək asanlaşır.
Avtomatlaşdırmaİnfrastruktur saniyələr və ya dəqiqələr içində qurulur, dəyişdirilir — insan səhvi riski kəskin azalır.
Qeyd. Deklarativ yanaşma "nəyi istəyirəm" sualına cavab verir, imperativ yanaşma isə "necə edim" sualına. Terraform deklarativdir: sən nəticəni yazırsan, addımların ardıcıllığını alət özü hesablayır.

3 · Terraform necə işləyir

Dörd addımlı iş dövrəsi

Terraform infrastruktur API-ları ilə (məsələn AWS və ya Azure API-ları) provider-lər vasitəsilə əlaqə qurur. Sadələşdirilmiş mənzərə belədir:

  1. Konfiqurasiya faylları. Arzu olunan vəziyyəti .tf fayllarında HCL ilə təsvir edirsən.
  2. terraform plan. Terraform sənin yazdığın konfiqurasiyanı infrastrukturun mövcud vəziyyəti ilə tutuşdurur və hərəkət planı hazırlayır.
  3. terraform apply. Terraform planda göstərilən dəyişiklikləri bulud provayderinin API-ları ilə əlaqə quraraq tətbiq edir: resurs yaradır, yeniləyir və ya silir.
  4. State faylı. Terraform idarə etdiyi resursları terraform.tfstate faylında qeyd edir. Bu fayl görülən işlərin qeydiyyat dəftəridir və gələcək dəyişikliklərin artımlı (incremental) şəkildə aparılmasına imkan verir.
Məsləhət. Bu dörd addımı ilk gündən vərdiş halına gətir: konfiqurasiyanı yaz → plan ilə oxu → nəticəni başa düşdükdən sonra apply et. plan-ı oxumadan apply etmək ən çox yayılmış səhvdir.

4 · Niyə məhz Terraform

a. Çoxbuludlu (multi-cloud) dəstək

Terraform-un ən diqqətəçarpan xüsusiyyətlərindən biri eyni anda bir neçə bulud provayderi ilə işləyə bilməsidir. Bir provayderə bağlı qalan alətlərdən (məsələn, AWS CloudFormation yalnız AWS üçündür) fərqli olaraq, Terraform infrastrukturu müxtəlif bulud mühitləri üzərində idarə etməyə imkan verir. Bu, multi-cloud və ya hibrid strategiya seçən təşkilatlar üçün xüsusilə dəyərlidir.

Məsələn, əsas infrastruktur üçün AWS EC2 instance-larını, məlumat saxlanması üçün Google Cloud Storage-ı, mikroservislərin yerləşdirilməsi üçün isə Azure Kubernetes Service-i — hamısını bir Terraform konfiqurasiyası daxilində idarə edə bilərsən. Bu çeviklik komandaları vendor lock-in-dən qoruyur və hər provayderin ən güclü tərəfindən istifadə etməyə imkan verir.

Sadə çoxbuludlu quruluş nümunəsi:

# AWS provider — Şimali Virciniya regionu
provider "aws" {
  region = "us-east-1"
}

# Google Cloud provider
provider "google" {
  project = "my-google-project"
  region  = "us-central1"
}

# AWS-də EC2 instance
resource "aws_instance" "my_aws_instance" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
}

# Google Cloud-da storage bucket
resource "google_storage_bucket" "my_bucket" {
  name     = "my-storage-bucket"
  location = "US"
}

b. Deklarativ sintaksis

Terraform infrastrukturun təsviri üçün deklarativ modeldən istifadə edir. Yəni sən infrastrukturun necə görünməli olduğunu yazırsan, bu vəziyyətə hansı yolla çatılacağını isə Terraform həll edir. EC2 instance yaratmaq üçün hər addımı əl ilə göstərmək əvəzinə, sadəcə son nəticəni təyin edirsən.

Bu, imperativ yanaşmanın əksidir — orada hər iş üçün addım-addım göstəriş yazmaq lazımdır. Terraform-un deklarativ təbiəti sayəsində konfiqurasiya faylları daha oxunaqlı, daha yığcam və səhvə daha az meyllidir.

c. Modul əsaslı infrastruktur

Terraform module-lardan istifadəni təşviq edir. Module — müxtəlif layihələrdə təkrar istifadə oluna bilən, öz-özünə tam olan infrastruktur komponentidir. Bu, infrastrukturu modul quruluşlu və genişlənə bilən edir. Texniki baxımdan module sadəcə .tf faylları olan bir qovluqdur və bir qrup resursu öz içində qablaşdırır.

Məsələn, VPC üçün ayrı module, EC2 instance-lar üçün başqa module, load balancer-lər üçün üçüncü module yaza bilərsən. Sonra bu module-ları kodu təkrarlamadan bütün mühitlərdə (development, staging, prod) işlədirsən.

# Module-un təyini (modules/vpc/main.tf)
module "vpc" {
  source     = "./modules/vpc"
  cidr_block = "10.0.0.0/16"
}

# Module-un əsas konfiqurasiyada işlədilməsi
module "my_vpc" {
  source     = "./modules/vpc"
  cidr_block = "10.0.0.0/16"
}

Module-lardan istifadə etməklə infrastrukturu müxtəlif layihələr arasında asanlıqla nizamlaya və standartlaşdıra bilərsən.

d. State — infrastrukturun vəziyyətinin izlənməsi

Terraform infrastrukturun vəziyyətini terraform.tfstate faylı vasitəsilə izləyir. Bu fayl mövcud infrastrukturun anlıq şəklidir (snapshot) və Terraform-a hansı resursların artıq mövcud olduğunu, hansıların dəyişdirilməli, hansıların silinməli olduğunu bildirir.

State faylı sayəsində Terraform artımlı yeniləmələr apara bilir — yalnız lazım olan dəyişikliklər tətbiq olunur. Beləliklə bütün infrastrukturu yenidən qurmağa ehtiyac qalmır, bu isə həm vaxta qənaətdir, həm də səhv riskini azaldır.

Saxlanma yeriİzahatNə vaxt uyğundur
LokalState faylı Terraform-un işlədiyi maşında saxlanılır.Təkbaşına təcrübə, öyrənmə mərhələsi
Remote (uzaq)State faylı Amazon S3, Azure Blob Storage kimi xidmətlərdə saxlanılır.Bir neçə nəfərin eyni infrastruktur üzərində işlədiyi komandalar
Diqqət. State faylında açıq mətnlə həssas məlumatlar (parollar, açarlar) ola bilər. Onu heç vaxt Git repozitoriyasına yükləmə və komanda işində mütləq remote backend işlət.

5 · Terraform-un əsas imkanları

a. Execution plan — dəyişikliklərə əvvəlcədən baxış

Terraform-un execution plan imkanı dəyişiklikləri tətbiq etməzdən əvvəl onlara baxmağa imkan verir. terraform plan işlədəndə Terraform infrastrukturun mövcud vəziyyətini (state faylındakı) konfiqurasiyada təsvir olunmuş arzu olunan vəziyyətlə tutuşdurur. Nəticədə hansı addımların atılacağını göstərən plan yaranır: yeni resursların yaradılması, mövcudların yenilənməsi və ya köhnəlmişlərin silinməsi.

terraform plan

Nümunə nəticə:

+ aws_instance.my_instance
    ami:           "ami-0c55b159cbfafe1f0"
    instance_type: "t2.micro"

Plan: 1 to add, 0 to change, 0 to destroy.

Bu imkan dəyişiklikləri tətbiq etməzdən əvvəl nəzərdən keçirmək fürsəti yaradır və iş mühitində təsadüfi dəyişiklik riskini azaldır.

b. Resource graph — asılılıq qrafı

Terraform resurslar arasındakı əlaqələri təsvir edən asılılıq qrafı qurur. Asılılıqları başa düşdüyü üçün hansı resursların paralel yaradıla biləcəyini, hansıların isə müəyyən ardıcıllıqla yaradılmalı olduğunu özü müəyyən edir.

Məsələn, bir-birindən asılı olmayan EC2 instance və S3 bucket paralel yaradıla bilər. Amma EC2 instance əvvəlcə yaradılmalı olan VPC-yə bağlıdırsa, Terraform VPC-nin əvvəl qurulmasını təmin edəcək.

c. Zəngin provider ekosistemi

Terraform-un çox geniş provider ekosistemi var. Provider-lər bulud platformaları və digər API-larla əlaqə qurmağa cavabdehdir. Ən çox işlədilənlər:

Providerİdarə etdiyi resurslar
AWSEC2 instance-lar, S3 bucket-lər, RDS verilənlər bazaları və s.
AzureVirtual Machine-lər, App Service-lər, Azure Kubernetes Service (AKS)
Google CloudCompute Engine, Cloud Storage, Google Kubernetes Engine (GKE)
KubernetesKubernetes klasterləri və içindəki resurslar — Kubernetes infrastrukturunu kod kimi idarə etmək

d. Modulluq və təkrar istifadə

Yuxarıda qeyd olunduğu kimi, Terraform module-ları dəstəkləyir. Module-lar kodun təkrar istifadəsini asanlaşdırır və infrastruktur kodunu nizamlı saxlamağa kömək edir. Xüsusilə yüzlərlə və ya minlərlə resursun idarə olunduğu böyükmiqyaslı infrastrukturlarda əvəzsizdir.

Məsələn, VPC təyin edən bir module bütün mühitlərdə işlədilə bilər — bu da bütün mühitlərdə eyni şəbəkə konfiqurasiyasını təmin edir.

e. Birgə iş və versiya nəzarəti

Terraform konfiqurasiyaları Git kimi versiya nəzarəti sistemlərində saxlanıla bilər. Bu, komandalara infrastruktur üzərində eynilə tətbiq kodu kimi birgə işləmək imkanı verir. Konfiqurasiyadakı hər dəyişiklik versiya tarixçəsində qeyd olunur: dəyişiklikləri audit etmək, problemli yeniləmələri geri qaytarmaq və komandalararası əməkdaşlıq asanlaşır.

Əlavə fikir. Infrastruktur kodunu tətbiq kodu ilə eyni səviyyədə cidd-cəhdlə idarə et: pull request, kod baxışı (code review), CI-da terraform plan-ın avtomatik işlədilməsi. Bu vərdişlər infrastruktur səhvlərinin böyük hissəsini prod-a çatmamış tutur.

6 · Terraform-un quraşdırılması

Ümumi mənzərə

Terraform Linux, macOS və Windows üzərində quraşdırıla bilər. Quraşdırma sadədir: binar faylı yükləyib sistemin PATH-inə əlavə etmək kifayətdir.

a. Linux-da quraşdırma

1. Binar faylı yüklə. Rəsmi yükləmə səhifəsindən son versiyanı götür və ya wget işlət:

wget https://releases.hashicorp.com/terraform/1.0.0/terraform_1.0.0_linux_amd64.zip

2. Arxivi aç. Yükləmədən sonra faylı açıb icra olunan sənədi əldə et:

unzip terraform_1.0.0_linux_amd64.zip

3. Binar faylı /usr/local/bin/-ə köçür ki, istənilən terminal seansından çağırıla bilsin:

sudo mv terraform /usr/local/bin/

4. Quraşdırmanı yoxla:

terraform --version

Ekranda quraşdırılmış versiya görünməlidir — bu, quraşdırmanın uğurlu olduğunu təsdiqləyir.

b. macOS-da quraşdırma

macOS-da Terraform-u Homebrew paket meneceri ilə quraşdırmaq ən rahat yoldur.

1. Homebrew-u quraşdır (əgər hələ yoxdursa). Homebrew macOS üçün geniş yayılmış paket menecerdir və bir çox alətin, o cümlədən Terraform-un quraşdırılmasını asanlaşdırır:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

2. Terraform-u quraşdır:

brew install terraform

3. Yoxla:

terraform --version

c. Windows-da quraşdırma

Windows-da binar faylı əl ilə yükləmək və ya Chocolatey paket menecerindən istifadə etmək olar.

1. Chocolatey ilə. Chocolatey artıq quraşdırılıbsa, administrator hüquqlu əmr sətrində:

choco install terraform

2. Əl ilə quraşdırma. Rəsmi saytdan Windows binar faylını yüklə, zip arxivini aç və terraform.exe faylını PATH mühit dəyişəninə daxil olan bir qovluğa yerləşdir (məsələn C:\Windows\System32).

3. Yoxla. Command Prompt pəncərəsini aç və versiyanı soruş:

terraform --version
Məsləhət. Kursda göstərilən 1.0.0 versiyası nümunə üçündür. Praktikada hər zaman güncəl sabit versiyanı işlət və komanda daxilində eyni versiyada dayan — versiya fərqi state faylında gözlənilməz nəticələr verə bilər.

7 · Terraform konfiqurasiyasının əsasları

a. Konfiqurasiyanın quruluşu

Terraform quraşdırıldıqdan sonra növbəti addım infrastrukturu idarə etməyə başlamaq üçün sadə bir konfiqurasiya yaratmaqdır. Terraform HCL dilində yazılmış konfiqurasiya fayllarından istifadə edir.

Sadə Terraform konfiqurasiyası üç əsas hissədən ibarətdir:

  • Provider-lər — bulud provayderini və ya infrastruktur platformasını təyin edir.
  • Resource-lar — idarə olunacaq infrastruktur resurslarını təsvir edir.
  • Dəyişənlər və output-lar — dəyişənlər konfiqurasiyaya çeviklik gətirir, output-lar isə yerləşdirmədən sonra faydalı məlumat qaytarır.

Aşağıda Terraform ilə AWS EC2 instance qurmağın sadə nümunəsini addım-addım keçirik.

b. Provider-in təyini

Provider infrastruktur resurslarının yaradılmasına və idarəsinə cavabdehdir. Resurs yaratmazdan əvvəl işlədiyin platforma üçün provider-i təyin etməlisən.

provider "aws" {
  region     = "us-west-1"
  access_key = "your-access-key"
  secret_key = "your-secret-key"
}
  • provider bloku AWS ilə əlaqə qurmaq üçün lazım olan konfiqurasiyanı təyin edir.
  • Giriş açarlarını ya birbaşa konfiqurasiyada göstərə bilərsən (təhlükəsizlik baxımından təklif olunmur), ya da AWS_ACCESS_KEY_ID və AWS_SECRET_ACCESS_KEY mühit dəyişənlərindən istifadə edə bilərsən.
Xəbərdarlıq. Açarları .tf faylının içinə yazmaq ən təhlükəli vərdişlərdən biridir — fayl Git-ə düşən kimi açarlar sızır. Mühit dəyişənləri, AWS profil faylı və ya IAM rolu işlət.

c. Resource-ların təyini

Provider təyin olunandan sonra resursları yazmağa başlaya bilərsən. Resource-lar infrastrukturun təməl komponentləridir: virtual maşınlar, yaddaş, şəbəkələr.

resource "aws_instance" "example" {
  ami           = "ami-0c55b159cbfafe1f0" # Amazon Linux AMI
  instance_type = "t2.micro"
}
  • resource bloku AWS-də bir EC2 instance təyin edir. AMI (Amazon Machine Image) instance-ın əməliyyat sistemini, instance_type isə ölçüsünü müəyyən edir.
  • aws_instance.example adı Terraform-un bu resursu daxildə tanıması üçün işlədilir.

d. Dəyişənlər

Terraform konfiqurasiyaları daha dinamik və təkrar istifadəyə yararlı etmək üçün dəyişənləri dəstəkləyir. Instance tipi və ya region kimi dəyərləri koda sabit yazmaq əvəzinə dəyişən təyin edirsən.

variable "instance_type" {
  default = "t2.micro"
}

resource "aws_instance" "example" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = var.instance_type
}

Yuxarıdakı nümunədə instance_type adlı dəyişən təyin olunub və resource blokunda var.instance_type ilə ona müraciət edilir.

Dəyişənlər həm də terraform apply zamanı əmr sətri arqumenti kimi ötürülə bilər — bu, konfiqurasiya fayllarına toxunmadan dəyərləri dəyişməyə imkan verir.

e. Output-lar

Output-lar infrastruktur qurulduqdan sonra ondan dəyər çıxarmaq üçündür. Bu, konfiqurasiyalar arasında məlumat ötürmək və ya IP ünvanı, resurs ID-si kimi vacib məlumatları göstərmək baxımından faydalıdır.

output "instance_ip" {
  value = aws_instance.example.public_ip
}

Konfiqurasiya tətbiq olunduqdan sonra EC2 instance-ın public IP ünvanı ekrana çıxacaq. Output dəyərlərinə infrastruktur qurulduqdan sonra belə müraciət edə bilərsən:

terraform output instance_ip

f. Layihənin ilkin hazırlanması — terraform init

Hər hansı Terraform əmrini işlətməzdən əvvəl layihəni ilkin vəziyyətə gətirmək lazımdır. terraform init əmri lazımi provider plugin-lərini yükləyir və iş mühitini qurur.

terraform init

Bu əmr .tf fayllarının yerləşdiyi qovluqdan işlədilir. İlkin hazırlıqdan sonra Terraform infrastrukturu idarə etməyə hazırdır.

g. Plan və apply

Konfiqurasiya hazır olduqda növbəti addım Terraform-un edəcəyi dəyişikliklərə baxmaqdır. Bunun üçün terraform plan işlədilir:

terraform plan

Nəticə hansı resursların yaradılacağını, dəyişdiriləcəyini və ya silinəcəyini göstərir. Bu, iş mühitindəki infrastrukturu təsadüfən dəyişməmək üçün kritik addımdır.

Plandan razı qaldıqdan sonra dəyişiklikləri terraform apply ilə tətbiq edirsən:

terraform apply

Bu, Terraform-u bulud provayderi (bu halda AWS) ilə əlaqəyə keçməyə və konfiqurasiyada təyin olunmuş resursları yaratmağa vadar edir.

h. State idarəsi

Terraform idarə etdiyi resursları state faylı vasitəsilə izləyir. terraform.tfstate faylı infrastrukturun cari vəziyyətini saxlayır və Terraform-un artımlı dəyişiklikləri idarə etmə qabiliyyəti üçün həlledicidir.

Standart olaraq state faylı iş qovluğunda lokal saxlanılır, lakin Amazon S3, Azure Blob Storage və ya Google Cloud Storage kimi xidmətlərdə uzaqda da saxlanıla bilər. Remote state bir neçə komanda üzvünün eyni infrastruktur üzərində işlədiyi hallarda vacibdir.

Cari vəziyyəti gözdən keçirmək üçün:

terraform show

i. Təmizləmə — terraform destroy

İnfrastrukturla işin bitəndə və resursları silmək istədikdə terraform destroy əmrini işlədirsən. Bu əmr Terraform-un yaratdığı bütün resursları silir.

terraform destroy

Terraform silməyə başlamazdan əvvəl təsdiq istəyəcək.

Diqqət. destroy geri qaytarılmayan əmrdir. Hansı qovluqda və hansı workspace-də olduğunu mütləq yoxla — səhv qovluqda işlədilən bir destroy bütöv mühiti silə bilər.

j. Konfiqurasiyaların nizamlanması

İnfrastruktur böyüdükcə Terraform konfiqurasiyalarını module-lara və ya ayrı fayllara bölmək vacib olur. Resursları bir neçə .tf faylına ayırmaq və ya module işlətmək kodu nizamlı və təkrar istifadəyə yararlı saxlayır.

/project
 ├── main.tf
 ├── variables.tf
 ├── outputs.tf
 └── modules
     └── vpc
         ├── main.tf
         ├── variables.tf
         └── outputs.tf

Belə bölgü müxtəlif komandaların infrastrukturun ayrı-ayrı hissələri üzərində bir-birinə mane olmadan işləməsinə imkan yaradır.

Qeyd. Fayl adları Terraform üçün məcburi deyil — alət qovluqdakı bütün .tf fayllarını birləşdirib oxuyur. main.tf, variables.tf, outputs.tf sadəcə geniş yayılmış və oxunaqlılığı artıran razılaşmadır.

8 · Yadda saxla

  • Terraform deklarativ IaC alətidir: sən nəticəni təsvir edirsən, alət isə ona çatmaq yolunu özü hesablayır.
  • İş dövrəsi dəyişmir: init → plan → apply, işin sonunda isə lazım gələrsə destroy.
  • State faylı Terraform-un yaddaşıdır — onsuz artımlı dəyişikliklər mümkün deyil; komanda işində mütləq remote saxla.
  • Provider-lər Terraform-u xarici API-lara bağlayır; bir konfiqurasiyada bir neçə provider işlədilə bilər.
  • Module-lar kodun təkrarını aradan qaldırır və mühitlər arasında eyni quruluşu təmin edir.
  • Credential-ları heç vaxt konfiqurasiya faylına yazma — mühit dəyişənləri və ya IAM rolu işlət.
