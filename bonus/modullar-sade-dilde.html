Modullar — Sadə Dildə BONUS

Terraform + Copilot Modulu · DPE-07 · Modul nədir, necə işləyir və Copilot bunu necə asanlaşdırır

Bir cümlə ilə: modul — bir dəfə yazıb, dönə-dönə istifadə etdiyin hazır kod paketidir. Necə ki, tort reseptini bir dəfə yazırsan və hər dəfə fərqli ölçüdə tort bişirirsən — modulu da bir dəfə yazırsan və hər dəfə fərqli parametrlərlə infrastruktur "bişirirsən".

1 · Problem: kopyala-yapışdır kod

Kursda iki VPC yazdıq — kodları demək olar eyni idi, yalnız CIDR və ad fərqlənirdi:

resource "aws_vpc" "prd" {
  cidr_block = "10.0.0.0/16"
  tags = { Name = "prd" }
}
resource "aws_vpc" "dev" {
  cidr_block = "10.1.0.0/16"
  tags = { Name = "dev" }
}

İki dənə hələ dözüləndir. Bəs 10 mühit olsa? Bəs hər VPC-yə 5 yeni parametr əlavə etmək lazım gəlsə — 10 yerdə eyni düzəlişi edəcəksən? Bir yerdə unutsan — mühitlər bir-birindən fərqlənməyə başlayır və heç kim bilmir niyə.

✅ Həll: təkrarlanan hissəni bir yerə yığ (modul), fərqlənən hissəni parametr et (dəyişənlər). Düzəliş lazım olanda — bir yerdə düzəldirsən, hamı faydalanır.

Qovluqda belə görünür:

modules/vpc/
├── variables.tf   # nə QƏBUL edir: vpc_cidr_block, vpc_name
├── main.tf        # nə YARADIR: aws_vpc resursu
└── outputs.tf     # nə QAYTARIR: vpc_id
⚠️ Vacib qayda: mətbəxə kənardan girmək olmaz! Modulun içindəki resursa çölden birbaşa müraciət mümkün deyil — yalnız təhvil pəncərəsindən (output) ala bilərsən: module.vpc.vpc_id.

3 · Modulu çağırmaq = sifariş vermək

module "vpc" {
  source = "./modules/vpc"       # restoranın ünvanı (qovluq yolu)

  vpc_cidr_block = "10.2.0.0/16"  # sifarişin — "bu CIDR ilə"
  vpc_name       = "dev-vpc"      # sifarişin — "bu adla"
}

# Qəbzi istifadə etmək:
resource "aws_security_group" "sg" {
  vpc_id = module.vpc.vpc_id       # "vpc modulunun qaytardığı ID"
}

Adi dildə: "Ey vpc modulu! Sənə CIDR 10.2.0.0/16 və ad dev-vpc verirəm — mənə bir VPC yarat və ID-sini qaytar." Sabah eyni cümləni prd dəyərləri ilə deyirsən — ikinci VPC hazır, kod yazmadan.

✅ Üç qızıl qayda: (1) modulun dəyişən adları ümumi olsun (vpc_cidr_block, dev_cidr_block yox) — modul mühit adı bilməməlidir; (2) modul dəyişənlərinə default qoyma — dəyəri çağıran versin; (3) yeni modul əlavə etdin = terraform init unutma.

5 · Copilot ilə işləyəndə 3 tələ

  1. Ad uydurma: Copilot dəyişən adlarını "təxmin edir" — sənin yazdığınla hərfbəhərf düz gəlməyə bilər (kursda iki dəfə başımıza gəldi: vpc_cidr və dev_vpc_cidr_block). Ad tutmasa, terraform plan dərhal "undeclared variable/resource" deyəcək — xətanı oxu, adı düzəlt.
  2. Artıq səxavət: Copilot modul dəyişəninə default, lazımsız parametrlər, hətta artıq output təklif edə bilər — hamısını götürmə. Modul nə qədər sadə, o qədər yaxşı.
  3. Köhnə istinadlar: resursu modula çevirəndə köhnə istinadlar (aws_vpc.dev.id) qalır və plan xəta verir. Həll: module.vpc.vpc_id-yə dəyiş — və ya xətalı sətri seçib ⌘I → /fix.
✅ Dəyişməz qayda burada da işləyir: Copilot sürətləndirir, sən yoxlayırsan — modulda yoxlama üçlüyü: adlar üst-üstə düşür? → terraform init → terraform validate.

6 · Üç cümlədə yadda saxla

  1. Modul = resept: bir dəfə yaz, fərqli parametrlərlə dönə-dönə istifadə et.
  2. Üç qapısı var: variables (qəbul edir) → main (yaradır) → outputs (qaytarır) — içəriyə yalnız bu qapılardan girilir.
  3. Copilot skeleti və blokları saniyələrdə yazır — sənin işin adları tutuşdurmaq, artığı silmək və init + validate etməkdir.
