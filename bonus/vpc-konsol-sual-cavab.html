AWS Konsolunda Nə Görürəm? BONUS

Terraform + Copilot Modulu · DPE-07 · terraform apply-dan sonra VPC konsolunun izahı

terraform apply uğurla bitdi, AWS Console → VPC → prd VPC-sinə baxırsan… və ekran bizim yazmadığımız şeylərlə doludur: qəribə ID-lər, üçüncü route table, hansısa ACL, DHCP… Bu sənəd ilk baxışda yaranan sualların hamısına cavab verir. Qayda belədir: çaşdıran hər şeyin izahı ya "AWS-in avtomatik yaratdığı", ya da "identifikator vs ad" mövzusundadır.

Bölmə 1 · "Mən bunu yazmamışdım!" — avtomatik yaranan şeylər

1Mən VPC-yə "prd" adı vermişdim. Bəs bu vpc-0be9c8f38606c4096 nədir?

AWS-də hər resursun iki kimliyi var:

NəKim verirNümunəXüsusiyyəti
IDAWS, avtomatikvpc-0be9c8f...Unikal, dəyişməz — API bununla işləyir
NameSən, tags = { Name = "prd" } iləprdİnsan üçün etiket — istəsən dəyişə bilərsən

Terraform kodumuzda aws_vpc.prd.id yazanda məhz o uzun ID-ni götürürdük. Yadına gəlir — subnet-lər VPC-yə bu ID ilə bağlanırdı, adla yox.

✅ Qayda: ID = pasport nömrəsi (dəyişməz, rəsmi), Name tag = üstündəki stiker (oxumaq üçün).
2Biz 2 route table yazdıq (public + private). Niyə konsolda 3 görünür? rtb-0f98... haradan gəldi?

Üçüncüsü — main route table-dır və onu AWS özü yaradır, hər VPC ilə birlikdə, avtomatik. Sən istəsən də, istəməsən də hər VPC-nin bir main route table-ı olur.

Vəzifəsi: ehtiyat plan. Hansısa subnet heç bir route table-a açıq bağlanmasa (association yazılmasa), AWS onu susmaya görə main-ə bağlayır — subnet "xəritəsiz" qalmasın deyə.

Bizim 6 subnetin hamısının açıq association-u var (3 → public-rt, 3 → private-rt), ona görə main route table boş-boşuna dayanıb — Resource map-da heç bir subnetə xətti yoxdur. Diqqət etmisənsə!

✅ Dərsdəki qaydamızın səbəbi budur: hər subnetə açıq association yaz — hansı subnet hansı xəritə ilə işləyir, kod baxan hər kəsə aydın olsun.
3Main network ACL (acl-012851...) nədir? Biz ACL-də yazmamışdıq…

Network ACL (Access Control List) — subnet səviyyəsində trafik firewall-udur: hansı paketlər girə/çıxa bilər. Hər VPC ilə birlikdə AWS bir default ACL yaradır və o, susmaya görə hər şeyə icazə verir — ona görə şəbəkəmiz problemsiz işləyir.

Security Group ilə qarışdırma: SG resurs səviyyəsində (məsələn, bir EC2 instance-ın qapısı), ACL subnet səviyyəsində (bütöv məhəllənin girişi) işləyir. Bu kursda ikisinə də dərindən girmirik — sadəcə bil ki, avtomatik yaranır və default halda maneə törətmir.

4DHCP option set (dopt-01733...) nədir?

VPC daxilində işə düşən hər maşına IP ünvanı, DNS server ünvanı və s. paylamaq lazımdır — bunu DHCP edir. AWS hər VPC üçün hazır standart dəst qoşur: "IP-ləri belə payla, DNS kimi AWS-in öz serverini istifadə et".

Bu da avtomatik yaranan resurslardandır — 99% hallarda ona heç vaxt toxunmayacaqsan.

5Default VPC: No yazır. "Default VPC" nədir — mənim account-umda əvvəlcədən VPC var idi?

Bəli! AWS hər yeni account-da, hər regionda bir hazır "default VPC" yaradır — yeni başlayanlar heç nə qurmadan dərhal server işə sala bilsin deyə. "Your VPCs" siyahısında bizimkindən başqa bir VPC də görməyinin səbəbi budur.

Bizim prd VPC-si isə sıfırdan, Terraform ilə qurulub — ona görə Default VPC: No. Prod işlərində həmişə öz VPC-ni qurursan; default VPC "tez sınaq" üçündür.

⚠️ Default VPC-yə toxunma, silmə — Terraform onu tanımır (state-də yoxdur) və bizim destroy ona dəymir. Amma əl ilə silsən, geri qaytarmaq əziyyətlidir.

Bölmə 2 · Ekrandakı sahələr nə deyir?

6State: Available — başqa hansı vəziyyətlər olur?

VPC üçün əsasən iki vəziyyət görəcəksən: pending (yaradılır, bir neçə saniyə) və available (hazır, işləyir). Available = hər şey qaydasındadır, resurs istifadəyə hazırdır.

7Tenancy: default nə deməkdir?

VPC-də işə salınacaq maşınların fiziki yerləşməsi haqqındadır: default = maşınlar AWS-in ortaq fiziki serverlərində işləyir (hamı kimi, standart və ucuz yol). Alternativ dedicated = sənə ayrılmış fiziki server — xüsusi compliance tələbləri üçündür və xeyli bahadır. Həmişə default istifadə edəcəyik.

8DNS resolution: Enabled, amma DNS hostnames: Disabled — bu ziddiyyət deyil?

İki ayrı şeydir:

DNS resolution = VPC içindəki maşınlar ünvanları həll edə bilir (məsələn google.com → IP). Bu, açıqdır — internetə çıxan maşınlar üçün lazımdır.

DNS hostnames = AWS hər maşına avtomatik ad versin (ip-10-0-1-5.eu-north-1.compute.internal kimi). Biz kodda bunu açmadıq, ona görə bağlıdır — hələlik lazımımız da yoxdur.

✅ Yeri gəlmişkən: modul dərsində (Fəsil 4.5) enable_dns_hostnames = true yazacağıq — o zaman bu sahə Enabled olacaq.
9Owner ID: 044015804971 — bu nədir?

Sənin AWS account nömrəndir — 12 rəqəmli unikal identifikator. aws sts get-caller-identity əmrində gördüyün nömrənin eynisi. Resursun "sahibi kimdir" sualına cavab verir — məsələn, resursları account-lar arasında paylaşanda vacib olur.

10IPv6 pool: – və bəzi sahələr niyə boşdur?

Biz VPC-yə yalnız IPv4 diapazonu verdik (10.0.0.0/16). IPv6 istəməli olsaydıq, kodda ayrıca yazardıq. "–" = "bu funksiya bu VPC üçün konfiqurasiya olunmayıb" deməkdir — xəta deyil, sadəcə istifadə etmirik. Eyni məntiq digər boş sahələrə də aiddir (Encryption control, Route 53 firewall və s.).

Bölmə 3 · Resource map-ı necə oxumalı?

11Subnetlər niyə eu-north-1a / 1b / 1c qrupları altında düzülüb və yanlarındakı A/B/C hərfləri nədir?

Bu qruplaşma Availability Zone-lara görədir — konsol subnetləri fiziki yerləşdiyi zonaya görə göstərir. A/B/C nişanları da elə zonanın qısaltmasıdır.

Bax, memarlıq slaydımızdakı plan birə-bir reallaşıb: hər zonada 1 public + 1 private subnet. Bir zona çöksə, qalan iki zonadakı subnetlər işləyir — redundantlığın konsoldakı görüntüsü budur.

12Subnetlərdən route table-lara gedən xətlər nəyi göstərir? Və niyə prd-igw "Network Connections" adlanır?

Xətlər = bizim yazdığımız route table association-lardır! Hər xətt bir aws_route_table_association resursudur: pub-subnet-lərdən prd-public-rt-yə 3 xətt, pri-subnet-lərdən prd-private-rt-yə 3 xətt. Naviqator analogiyasını xatırla: xətt = telefonun maşına bərkidilməsi.

prd-igw isə "Network Connections" sütunundadır, çünki Internet Gateway VPC-nin kənar dünyaya bağlantısıdır — konsol bütün "başqa şəbəkələrə çıxışları" (IGW, NAT, VPN, peering) bu sütunda göstərir. Bizdə yalnız biri var: internetə qapı.

✅ Sınaq: prd-public-rt-nin üstünə mausu gətir — bağlı subnetlər işıqlanır və IGW-yə marşrut görünür. prd-private-rt-də isə kənar bağlantı yoxdur. Fərq — gözünün qabağında.

Bölmə 4 · Praktik suallar

13Bu resurslar pul yeyir? Gecə açıq qalsa nə olar?

Xeyr — bu 16 resursun hamısı pulsuzdur: VPC, subnet, route table, association, IGW — AWS bunlara görə pul almır. Gecə qalsa da xərc sıfırdır.

⚠️ Amma vərdiş vərdişdir: dərs bitəndə terraform destroy. Çünki sabah memarlıqda pullu resurs olacaq (EC2, NAT…) və "onsuz da pulsuzdur" düşüncəsi o gün baha başa gələr. Zero-spend budget alert-in də elə bunun üçündür.
14Konsoldan əl ilə bir subneti silsəm nə baş verər?

AWS silər — amma Terraform-un state faylı bundan xəbərsizdir: state hələ də "6 subnet var" deyir. Buna drift (sürüşmə) deyilir: kod ↔ state ↔ AWS bir-birindən ayrı düşür.

Növbəti terraform plan fərqi görəcək və deyəcək: "1 to add" — silinən subneti bərpa etməyi təklif edəcək. apply etsən, subnet geri qayıdır. Terraform-un gücü budur: kodda yazılan = mövcud olmalı olan.

✅ Qızıl qayda: Terraform ilə qurulan infrastruktura əl ilə toxunma — hər dəyişiklik kodda edilir, apply ilə tətbiq olunur.
15Region seçicisində Europe (Stockholm) yazır. Başqa regiona keçsəm resurslarım görünəcək?

Xeyr! AWS konsolu həmişə bir regionun resurslarını göstərir. Sənin VPC-n eu-north-1-də (Stokholm) yaşayır — konsolda başqa region seçsən, siyahı "boş" görünəcək və ilk anda "resurslarım silinib?!" təəssüratı yaranar. Silinməyib — sadəcə başqa şəhərə baxırsan.

✅ "Resurslarım yoxa çıxıb" panikasının 1 nömrəli səbəbi yanlış regiondur. Əvvəl sağ yuxarı künc: Stockholm seçilib?
