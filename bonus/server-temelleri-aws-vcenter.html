Server Qurmazdan Əvvəl Nə Lazımdır? BONUS

Terraform + Copilot Modulu · DPE-07 · AWS və vCenter-də serverin təməl qatları — Terraform-dan əvvəlki dünya

Bir virtual server (VM) heç vaxt boşluqda yaranmır — onun altında təməl qatlar olmalıdır: işləyəcəyi yer (compute), qoşulacağı şəbəkə, diskinin yaşayacağı storage, üzərinə qurulacağı image və bütün bunlara toxunmaq üçün giriş icazələri.

Analogiya: ev tikintisi — ev (server) tikilməzdən əvvəl torpaq sahəsi (compute), yol və kommunikasiyalar (şəbəkə), su-elektrik xətləri (storage), tikinti layihəsi (image) və tikinti icazəsi (credentials) lazımdır. Bu sənəd iki dünyanı yan-yana qoyur: ☁️ AWS və 🏢 vCenter (on-prem VMware) — və əsas suala cavab verir: Terraform-a başlamazdan əvvəl nəyi hazırlamalıyıq?

1 · Serverin beş təməl qatı — iki dünyada adları

Qat ☁️ AWS-də 🏢 vCenter-də
⚙️ Compute
"harada işləyəcək?"		 Fiziki qat görünməzdir — sadəcə instance tipi seçirsən (t3.micro: 2 vCPU, 1 GB RAM). Serverlər Amazon-undur. ESXi host (fiziki server + hypervisor) → Cluster (host qrupu) → Resource Pool (CPU/RAM bölgüsü). Dəmiri sən idarə edirsən.
🌐 Şəbəkə
"necə danışacaq?"		 VPC → Subnet (AZ-də) → Security Group (firewall) → IGW / Route Table (internetə yol). Fəsil 4-də qurduqlarımız! vSwitch / Distributed Switch (virtual kommutator) → Port Group (VM-in qoşulduğu "port") → VLAN (şəbəkə seqmenti). Fiziki switch-lərlə uzlaşmalıdır.
💾 Storage
"diski harada yaşayacaq?"		 EBS volume — instance-a qoşulan virtual disk. Növü seçirsən (gp3, io2), arxasındakı avadanlıq Amazon-un işidir. Datastore — host(lar)ın gördüyü disk sahəsi: lokal disk, SAN/iSCSI, NFS və ya vSAN. VM-in diski orada VMDK faylı kimi yaşayır.
📀 Image
"OS haradan gələcək?"		 AMI (Amazon Machine Image) — hazır OS şablonları marketplace-də var: Ubuntu, Amazon Linux… Seç və işə sal. VM Template — özün hazırlamalısan: bir VM qur, OS + VMware Tools quraşdır, template-ə çevir. Terraform template yaratmır, ondan clone edir.
🔑 Giriş
"kim yaratmağa icazəlidir?"		 IAM user/role + access key (Terraform üçün) və key pair (hazır serverə SSH üçün). vCenter istifadəçisi + rol/icazələr (Terraform üçün) və template-in daxilindəki guest OS hesabı (hazır VM-ə giriş üçün).
🔢 IP ünvanı
"ünvanı kim verəcək?"		 Private IP — subnetdən avtomatik. Kənardan giriş lazımdırsa: Public IP / Elastic IP. DHCP (şəbəkədə varsa) və ya static IP — clone zamanı customization ilə verilir. DHCP yoxdursa, IP planlaması sənin üzərinə düşür.

2 · Əsas sual: Terraform-dan ƏVVƏL nə hazır olmalıdır?

☁️ AWS — siyahı qısadır

  • AWS account (+ billing məlumatı)
  • Budget alert (zero-spend) — xərc siqnalizasiyası
  • IAM user + access key-lər (Terraform-un girişi)
  • Region qərarı (bizdə: eu-north-1)
✅ Vəssalam. Qalan hər şeyi — VPC, subnet, storage, server — Terraform özü yarada bilir, image-lər (AMI) hazır gəlir. Cloud-un mahiyyəti budur: təməl qatlar API arxasında hazırdır.

🏢 vCenter — təməli özün tikirsən

  • Fiziki server(lər) + ESXi quraşdırılmış
  • vCenter deploy edilmiş (VCSA appliance)
  • vCenter-də Datacenter + Cluster yaradılmış, host əlavə edilmiş
  • Datastore qoşulmuş (lokal/SAN/NFS/vSAN)
  • Şəbəkə: vSwitch + Port Group + VLAN-lar (fiziki switch-lərlə uzlaşmış)
  • VM Template hazırlanmış (OS + VMware Tools)
  • DHCP və ya IP planı
  • Terraform üçün vCenter istifadəçisi + icazələr
⚠️ Bunların heç birini Terraform yaratmır — bunlar infrastrukturun fiziki/platforma qatıdır. Terraform yalnız hazır təməlin üstündə VM-ləri idarə edir.

3 · Bəs Terraform bu hazır şeyləri necə görür? — data source

Fəsil 2-dən xatırla: Terraform-un iki əsas bloku var — resource (yaradır) və data source (mövcudu tapır). vCenter dünyasında data source əsas işçidir: əvvəlcədən qurulmuş datastore-u, şəbəkəni, template-i axtarıb tapırıq, sonra VM resursu onların üstündə yaranır:

data: datacenter 🔍→ data: datastore 🔍→ data: network (port group) 🔍→ data: template 🔍→ resource: virtual_machine ✚

AWS-də isə əksinə — demək olar hər şey resource-dur, çünki hər şeyi Terraform özü yarada bilir. Data source AWS-də də var (məsələn, hazır AMI-ni tapmaq üçün), amma çəkisi azdır.

✅ Yadda saxlama düsturu: cloud = çox resource, az data source · on-prem = əvvəl data source-larla təməli tap, sonra resource ilə VM yarat.

5 · Yekun checklist — "terraform init-dən əvvəl"

☁️ AWS layihəsinə başlayırsan:

  • Account var, budget alert qurulub?
  • IAM açarları var və aws sts get-caller-identity düzgün account göstərir?
  • Region seçilib və hər yerdə eynidir (provider + AZ-lər)?
  • Nə quracağını bilirsən? (memarlıq şəkli — Fəsil 4 qaydası)

🏢 vCenter layihəsinə başlayırsan:

  • vCenter ünvanı + Terraform istifadəçisi əlindədir?
  • Hansı datacenter / cluster / datastore? (adlarını dəqiq bil — data source-lar adla axtarır!)
  • Hansı port group / VLAN? IP-ni kim verir — DHCP, yoxsa static plan?
  • Template hazırdır və adını bilirsən?
✅ Bir cümləlik yekun: AWS-də Terraform-dan əvvəl yalnız hesab və açarlar lazımdır — təməli bulud verir; vCenter-də isə təməlin özü (host, storage, şəbəkə, template) əvvəlcədən qurulmalıdır — Terraform o təməl üzərində virtual qatı idarə edir. Hər iki halda iş axını eynidir: init → plan → apply → destroy.
