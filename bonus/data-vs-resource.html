data vs resource — Terraform-un İki Bloku BONUS

DPE-07 · Yaratmaq vs tapmaq · AWS və vSphere nümunələri ilə

Terraform kodunda əsasən iki cür blok görürsən: resource və data. Fərqi bir cümlədədir: resource yaradır və idarə edir, data isə yalnız oxuyur. Bu sənəd həmin fərqi diaqramlarla, state davranışı ilə və öz kodumuzdan nümunələrlə açır.

1 · Ən sadə şəkil

✚ resource — YAZMA (write)

"Bu obyekt mənimdir: yoxdursa yarat, fərqlidirsə düzəlt, kodan silsəm — sil."

resource "aws_vpc" "prd" {
  cidr_block = "10.0.0.0/16"
}

apply → VPC yaranır · destroy → VPC silinir

🔍 data — OXUMA (read)

"Bu obyekt başqasınındır: mən yalnız onu tapıb məlumatını götürürəm."

data "aws_availability_zones" "az" {
  state = "available"
}

apply → heç nə yaranmır · destroy → heç nə silinmir

✅ Yadda saxlama düsturu: resource = yazma · data = oxuma. Terraform yalnız yazdığına görə məsuliyyət daşıyır.

3 · Həyat dövrü — diaqramla

resource-un dövrü: Terraform obyektin bütün ömrünə cavabdehdir.

kod yazılır→ apply: yaradılır→ kod dəyişir → apply: düzəldilir→ destroy: silinir

data-nın dövrü: Terraform yalnız baxır — obyekt onun nəzarətindən kənardadır.

obyekt onsuz da mövcuddur→ plan: oxunur→ dəyəri kodda istifadə olunur→ destroy: obyektə toxunulmur
⚠️ Klassik yanlış anlama: "data silinəndə obyekt də silinir". Xeyr. Data blokunu koddan silsən — sadəcə həmin məlumatı oxumağı dayandırırsan. AWS-in availability zone-ları, vCenter-in datastore-u yerindədir.

4 · Bir kodda yan-yana: bizim AWS layihəmiz

# 🔍 DATA — AWS-in özündən oxuyuruq (biz yaratmırıq)
data "aws_availability_zones" "available" {
  state = "available"
}

# ✚ RESOURCE — biz yaradırıq, bizim məsuliyyətimizdədir
resource "aws_vpc" "prd" {
  cidr_block = "10.0.0.0/16"
}

# ✚ RESOURCE — və data-nın oxuduğu dəyəri istifadə edirik
resource "aws_subnet" "pub" {
  vpc_id            = aws_vpc.prd.id                                # ← resource istinadı
  availability_zone = data.aws_availability_zones.available.names[0]  # ← data istinadı
  cidr_block        = "10.0.1.0/24"
}
✅ Diqqət: istinadın başlanğıcı hər şeyi deyir — aws_vpc.prd.id (resource) vs data.aws_... (data). Kod oxuyanda ilk baxışdan bilirsən ki, obyekt bizimdir, yoxsa kənardan gəlir.

5 · vSphere: data-nın əsl gücü

On-prem-də nisbət tərsinə çevrilir — 5 data + 1 resource. Çünki datastore, şəbəkə, template onsuz da var, biz yalnız VM yaradırıq:

data "vsphere_datacenter" "dc"       { name = "Datacenter" }
data "vsphere_datastore" "ds"        { name = "datastore1" …}
data "vsphere_compute_cluster" "cl"  { name = "Cluster01" …}
data "vsphere_network" "net"         { name = "VM Network" …}
data "vsphere_virtual_machine" "tpl" { name = "ubuntu-2404-template" …}
resource "vsphere_virtual_machine" "vm" {
  datastore_id     = data.vsphere_datastore.ds.id          # tapılanı istifadə edir
  resource_pool_id = data.vsphere_compute_cluster.cl.resource_pool_id
  clone { template_uuid = data.vsphere_virtual_machine.tpl.id }
}
🤖 Maraqlı incəlik: vsphere_virtual_machine həm data, həm resource kimi mövcuddur! Eyni tip: data variantı mövcud VM/template-i tapır, resource variantı yeni VM yaradır. Adı eyni, işi tam fərqli.

6 · Nə vaxt hansını seçməli? — qərar ağacı

❓ Bu obyekti mən yaradıram?
BƏLİ → resource
  • Yeni VPC, subnet, VM, S3 bucket
  • Silinəndə getməlidir
  • Konfiqurasiyasını mən idarə edirəm
XEYR → data
  • Hazır AMI / template
  • Başqa komandanın VPC-si
  • Platformanın öz siyahıları (AZ-lər, regionlar)
  • Datastore, port group, cluster
✅ Praktik nisbət: cloud = çox resource, az data (hər şeyi özün yaradırsan) · on-prem = əvvəl data ilə təməli tap, sonra resource ilə yarat.

7 · Tez-tez verilən suallar

“data bloku state-də saxlanılır?”

Bəli, amma surət kimi — Terraform oxuduğu dəyərləri state-də saxlayır ki, planları müqayisə edə bilsin. Lakin bu qeyd obyektin sahibliyini vermir: destroy onu silmir.

“data dəyəri dəyişsə nə olar?”

Məsələn, ən son AMI yeniləndi və ya vCenter-də datastore adı dəyişdi. Növbəti plan-da data yenidən oxunur: ad tapılmasa — xəta; dəyər dəyişibsə — ondan asılı resurslarda dəyişiklik (bəzən replace) görünəcək.

⚠️ Ona görə "ən son AMI" tipli data-lardan prod-da ehtiyatlı istifadə edilir: image yeniləndikcə serverlər öz-özünə replace olunmasın deyə versiya sabitlənir.

“data blokunu silsəm, infrastruktura nə olar?

Heç nə. Yalnız həmin məlumatı oxumursan. Amma ona istinad edən resurslar varsa, kod xəta verəcək — əvvəlcə istinadları düzəlt.

“Mövcud obyekti idarə etməyə başlamaq istəyirəm — data kifayətdir?”

Xeyr. data yalnız oxuyur. İdarəni ələ almaq üçün import lazımdır: terraform import (və ya import bloku) mövcud obyekti state-ə resource kimi qeydiyyata alır.

8 · Üç cümlədə yadda saxla

  1. resource = yazma: yaradır, dəyişir, silir — Terraform onun sahibidir.
  2. data = oxuma: mövcud olanı tapır, dəyərini verir — heç nəyə toxunmur.
  3. İstinadın başında data. varsa — kənardan gələn məlumatdır; yoxdursa — sənin yaratdığın obyekt.
