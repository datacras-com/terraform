Plan: vCenter-də Terraform ilə VM PLAN

DPE-07 · On-prem praktika · AWS VPC planının vSphere qarşılığı

AWS tərəfdə əvvəlcə memarlıq şəkli çəkdik (VPC → subnet → IGW → route table), sonra kod yazdıq. Burada da eyni ardıcıllıq: əvvəl plan, sonra kod. Fərq budur ki, cloud-da təməli Amazon verirdi — on-prem-də təməli biz özümüz qururuq, Terraform isə onun üstündə VM-i yaradır. Bu sənəd üç suala cavab verir: (1) nə lazımdır, (2) nəyi Terraform yaradır, (3) hansı məlumatları toplamalıyıq.

1 · Məqsəd — nə quracağıq?

Bir "data pipeline VM": Ubuntu template-indən clone edilmiş, 2 vCPU / 4 GB RAM / 40 GB disk, şəbəkəyə qoşulu, adı və ölçüləri dəyişənlərdən gələn VM. AWS lab-ındakı məntiqin eynisi: əvvəl bir ədəd, sonra count/for_each ilə "fleet".

👤 Data Platform Engineer→ 📝 Terraform kodu→ 🔍 data source-lar (tapır)→ ✚ vsphere_virtual_machine (yaradır)→ 🖥️ İşlək VM

4 · Terraform-dan ƏVVƏL hazır olmalı (təməl)

Bunları Terraform yaratmır — mövcud olmalıdır:

  1. vCenter quraşdırılıb və ESXi host(lar) ona əlavə edilib
  2. Datacenter obyekti yaradılıb (adı lazım olacaq)
  3. Datastore qoşulub və boş yeri var (VM diski üçün ≥ 40 GB)
  4. Port Group (VM Network / VLAN) mövcuddur və işləkdir
  5. VM Template hazırdır: OS quraşdırılıb + VMware Tools / open-vm-tools quraşdırılıb (customization üçün şərtdir!), sonra "Convert to Template" edilib
  6. Terraform üçün vCenter istifadəçisi yaradılıb (VM yaratma icazələri ilə)
  7. IP planı: ya şəbəkədə DHCP var, ya da VM üçün boş static IP ayrılıb
⚠️ Ən çox unudulan: template-də VMware Tools yoxdursa, guest customization (host adı, IP təyini) işləmir — VM yaranır, amma şəbəkəsiz/adsız qalır.

4b · Ubuntu template-i necə hazırlanır? (addım-addım)

AWS-də AMI hazır gəlirdi — burada template-i özün hazırlayırsan. Bir dəfə edirsən, sonra ondan yüzlərlə VM clone olunur. Təxmini vaxt: 30–40 dəqiqə.

Addım 1 — ISO-nu datastore-a yüklə

  • Ubuntu Server 22.04 LTS ISO-nu endir (~2 GB)
  • vCenter → Storage → datastore seç → Files → Upload Files → ISO-nu yüklə (səliqə üçün əvvəlcə iso/ qovluğu yarat)

Addım 2 — Baza VM yarat

  • Datacenter-ə sağ klik → New Virtual Machine → Create a new virtual machine
  • Ad: ubuntu-2204-template-base · Guest OS: Linux → Ubuntu Linux (64-bit)
  • Resurslar: 2 vCPU · 2 GB RAM · 40 GB disk (Thin Provision) — sonra clone zamanı böyüdülə bilər
  • CD/DVD: Datastore ISO File → yüklədiyin ISO → Connect At Power On ✅ qeyd et
  • Şəbəkə: template üçün istifadə edəcəyin Port Group

Addım 3 — OS-u quraşdır

  • VM-i işə sal → Ubuntu quraşdırıcısı: dil, klaviatura, şəbəkə (DHCP), disk (bütöv disk, LVM)
  • İstifadəçi yarat — məsələn ubuntu (parolu yadda saxla, clone-lar bunu miras alacaq)
  • "Install OpenSSH server" seçimini mütləq işarələ ✅
  • Quraşdırma bitəndə: Reboot → ISO-nu ayır (CD/DVD → Disconnect)

Addım 4 — VM-in içini hazırla (ən vacib addım)

# Sistemi yenilə
sudo apt update && sudo apt upgrade -y

# ŞƏRTDİR: bunsuz Terraform customization (host adı, IP) İŞLƏMİR
sudo apt install -y open-vm-tools cloud-init

# Şablonu "təmiz" et — hər clone unikal olsun:
sudo cloud-init clean --logs                 # cloud-init tarixçəsi
sudo truncate -s 0 /etc/machine-id           # eyni machine-id = DHCP eyni IP verər!
sudo rm -f /var/lib/dbus/machine-id
sudo ln -s /etc/machine-id /var/lib/dbus/machine-id

# SSH host açarlarını sil (hər VM özünü yenidən yaratsın)
sudo rm -f /etc/ssh/ssh_host_*

# Tarixçə və müvəqqəti faylları təmizlə, sonra söndür
sudo apt clean && history -c
sudo shutdown -h now
⚠️ machine-id və SSH açarları təmizlənməsə: bütün clone VM-lər eyni kimliklə çıxır — DHCP onlara eyni IP verir və SSH xəbərdarlıqları başlayır. Ən çox rast gəlinən template səhvi budur.

Addım 5 — Template-ə çevir

  • VM söndürülmüş halda: sağ klik → Template → Convert to Template
  • Ad: ubuntu-2204-template — məhz bu adı Terraform-a verəcəyik (məlumat vərəqəsinə yaz!)
  • Yoxlama: VMs and Templates ağacında template ikonu ilə görünməlidir
✅ Nəticə: bir dəfəlik 30 dəqiqəlik iş — sonra hər terraform apply ondan 1–2 dəqiqəyə yeni VM çıxarır. Template-i sonradan yeniləmək lazım gəlsə: Convert to Virtual Machine → dəyişiklik et → yenidən template-ə çevir.
🤖 Sənayedə bu iş də avtomatlaşdırılır — HashiCorp Packer template-i koddan hazırlayır. Zəncir: Packer (template düzəldir) → Terraform (VM yaradır) → Ansible (içini konfiqurasiya edir).

5 · Kod strukturu — data source-lar və resurs

AWS-də demək olar hər şey resource idi. Burada 5 data source + 1 resource:

# providers.tf
terraform {
  required_providers {
    vsphere = {
      source  = "hashicorp/vsphere"
      version = "~> 2.12"
    }
  }
}

provider "vsphere" {
  # Giriş məlumatları env dəyişənlərindən oxunur:
  #   VSPHERE_SERVER / VSPHERE_USER / VSPHERE_PASSWORD
  allow_unverified_ssl = true   # yalnız test mühitində (self-signed sertifikat)
}
# main.tf — ƏVVƏL TAP (data), SONRA YARAT (resource)

data "vsphere_datacenter" "dc"      { name = var.datacenter }
data "vsphere_datastore" "ds"       { name = var.datastore
                                       datacenter_id = data.vsphere_datacenter.dc.id }
data "vsphere_compute_cluster" "cl" { name = var.cluster
                                       datacenter_id = data.vsphere_datacenter.dc.id }
data "vsphere_network" "net"        { name = var.network
                                       datacenter_id = data.vsphere_datacenter.dc.id }
data "vsphere_virtual_machine" "tpl"{ name = var.template
                                       datacenter_id = data.vsphere_datacenter.dc.id }

resource "vsphere_virtual_machine" "vm" {
  name             = var.vm_name
  resource_pool_id = data.vsphere_compute_cluster.cl.resource_pool_id
  datastore_id     = data.vsphere_datastore.ds.id

  num_cpus = var.cpu
  memory   = var.memory
  guest_id = data.vsphere_virtual_machine.tpl.guest_id

  network_interface {
    network_id   = data.vsphere_network.net.id
    adapter_type = data.vsphere_virtual_machine.tpl.network_interface_types[0]
  }

  disk {
    label            = "disk0"
    size             = var.disk_size
    thin_provisioned = true
  }

  clone {
    template_uuid = data.vsphere_virtual_machine.tpl.id

    customize {
      linux_options {
        host_name = var.vm_name
        domain    = var.domain
      }
      network_interface {}       # boş = DHCP
    }
  }
}
✅ Bu, "Server Təməlləri" sənədindəki düsturun canlı görüntüsüdür: on-prem = əvvəl data source ilə təməli tap, sonra resource ilə VM yarat.
🤖 Copilot bu kodu böyük ölçüdə özü yazacaq — amma ad sahələrini (datacenter, datastore, network, template adları) uydurmağa meyllidir. Onları yalnız sən verə bilərsən: aşağıdakı vərəqədən.

7 · İş axını və yoxlama

# 1) Giriş məlumatları (parol kodda YOX!)
$ export VSPHERE_SERVER="vcenter.local"
$ export VSPHERE_USER="terraform@vsphere.local"
$ export VSPHERE_PASSWORD="••••••"

# 2) Tanış beş addım
$ terraform init          # vsphere provider endirilir
$ terraform validate
$ terraform plan          # gözlənilən: 1 to add
$ terraform apply
$ terraform destroy       # dərs sonu ritualı

Yoxlama: vCenter → VMs → VM görünür, işə düşüb, IP alıb → SSH ilə qoşul.

⚠️ Fərq: AWS-də destroy xərci dayandırırdı; burada isə resursu boşaldır (CPU/RAM/disk) — pul geri qayıtmır, çünki dəmir onsuz da alınıb.
